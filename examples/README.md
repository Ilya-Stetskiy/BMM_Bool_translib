# examples/ — минимальные автономные примеры использования библиотеки

Всё остальное в репозитории (`test_aig`/`test_bdd`/`test_anf`/`test_thr`,
`test_chains`, `test_real_datasets`) собрано вокруг общей тестовой
инфраструктуры `verify/` и Catch2 — если вы никогда не видели этот код и
хотите просто понять, как вызвать одну функцию трансляции из **своего**
приложения, эти тесты не самый быстрый источник ответа: main() для всех них
один на всех — `verify/test_main.cpp`, а сами тесты вызывают функции через
шаблонный `verify::run_translation_tests<X, Y>(...)`, а не напрямую.

Два файла здесь показывают минимальный путь без всего этого:

- **`quickstart_bdd.cpp`** — вызывает `bmm::tt_to_bdd`.
- **`quickstart_non_bdd.cpp`** — вызывает `bmm::tt_to_aig`.

Оба примера строят одну и ту же маленькую тестовую функцию (majority на 3
переменных) и печатают таблицу истинности результата — сравните файлы
бок о бок, чтобы увидеть, в чём именно разница.

## Почему это два разных файла, а не один

**Bdd — единственное из пяти представлений (`Aig`/`Bdd`/`Anf`/`Thr`/
`TruthTable`), которое требует глобальной инициализации перед использованием**
(`core/CONVENTIONS.md` п.6, правило 1). Sylvan (библиотека, реализующая
`bmm::Bdd` изнутри) параллелит операции над BDD через свой собственный
планировщик задач — Lace — и требует, чтобы весь код, трогающий
`sylvan::Bdd`, выполнялся внутри задачи, зарегистрированной этим
планировщиком. Вызов операций над `sylvan::Bdd` из потока, который никогда
не был зарегистрирован как Lace-воркер (например, прямо из `main()` без
обвязки ниже), падает в **SIGSEGV** внутри Sylvan (`llmsset_lookup`) — не
`Result<T>` с ошибкой, не C++-исключение, а падение процесса.

Обязательный ритуал (см. `quickstart_bdd.cpp`):

```cpp
lace_start(n_workers, deque_size);   // поднять пул Lace-воркеров
RUN(some_lace_task);                 // ваш код — ВНУТРИ этой задачи
lace_stop();                         // остановить пул
```

а внутри самой Lace-задачи (`VOID_TASK_0(...)`/аналоги) — ещё и:

```cpp
sylvan::sylvan_set_sizes(...);
sylvan::sylvan_init_package();
sylvan::sylvan_init_bdd();
// ... работа с bmm::Bdd/sylvan::Bdd ...
sylvan::sylvan_quit();
```

`Aig`/`Anf`/`Thr`/`TruthTable` не требуют НИЧЕГО из этого — см.
`quickstart_non_bdd.cpp`, где `main()` вызывает `tt_to_aig()` напрямую.

## Про `deque_size` — не берите дефолт Lace

`lace_start(n_workers, deque_size)` — второй аргумент это размер очереди
SPAWN-задач на воркер, и дефолт Lace для него **заметно меньше**, чем нужно
этой библиотеке на реальных (не игрушечных) входах. В этом же репозитории
уже находили этот краш на практике: построение `Bdd` из плотного ANF
(`anf_to_bdd`, реальный корпус n=100/10000 мономов) падало с

```
Lace fatal error: Task stack overflow! Aborting.
```

— это фатальная ошибка самого Lace (не C++-исключение, поймать её через
`try/catch` нельзя), вызванная нехваткой места в очереди для объёма
рекурсивных `Ite()`-вызовов Sylvan, а не нехваткой нативного C-стека
(`lace_set_stacksize()` эту проблему **не** решает — уже проверено
эмпирически). Подобранное экспериментально значение, при котором крах не
возникает на реальных нагрузках этого проекта:

```cpp
const size_t deque_size = 1ULL << 21;
```

(`1<<18` — крах воспроизводится, `1<<21` — нет). И `quickstart_bdd.cpp`, и
`verify/test_main.cpp`, и `verify/chain_tests.cpp`/`verify/
real_datasets_tests.cpp` используют именно это значение — если вы
инициализируете Lace в своём приложении, начните с него же, а не с дефолта.

## Сборка и запуск

```sh
cmake --build build --target example_quickstart_bdd example_quickstart_non_bdd
./build/example_quickstart_bdd
./build/example_quickstart_non_bdd
```
